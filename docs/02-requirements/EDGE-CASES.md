# Lumora Edge Cases

> Status: Proposal, pending approval. Source of truth: Phase 1 docs.

Each case states the decided behavior. Phase 1 rule IDs (BR-xxx) are cited as written. Cases marked Phase 2 or 3 apply when the related feature ships. Open questions are listed in PRD.md section 10 (U-7 covers EC-011, U-8 covers EC-020).

| EC ID | Scenario | Trigger | Expected behavior | Related FR/BR/NFR | Phase |
|---|---|---|---|---|---|
| EC-001 | Timer interrupted by refresh or tab close | User refreshes, closes the tab or loses the browser while a timer runs | Running state is stored with server timestamps at start, pause and resume. On reload the elapsed time is shown and the timer continues. The client sends a heartbeat every 60 s. With no heartbeat for more than 30 min the session closes at the last heartbeat (BR-006) and is flagged "auto-closed". | FR-040, FR-046, FR-052, FR-054, FR-021; BR-006; NFR-051 | MVP |
| EC-002 | Multiple active sessions | User starts a timer on a second tab or device | The second start is rejected and the user sees the prompt "Stop current session and start new?". Confirming stops the first session at server time, then starts the new one. For simultaneous starts, the first accepted wins (BR-011). | FR-053, FR-059; BR-011; NFR-053 | MVP |
| EC-003 | Overlapping plan entries | A plan entry is saved, edited or dragged onto a time that overlaps another | Allowed with a warning and a required confirmation (BR-026); drag-and-drop behaves the same (BR-027). Overlap is computed per user across all subjects. | FR-030, FR-031, FR-034, FR-065..067, FR-069; BR-026, BR-027 | MVP (forms), 2 (drag-and-drop) |
| EC-004 | Missed daily goal | A local day ends with progress below the goal | No penalty and no notification in the MVP. The day is marked "goal not met" in statistics. In Phase 2 the streak resets unless a freeze applies (BR-021). | FR-020, FR-073, FR-084, FR-161, FR-162; BR-015, BR-021 | MVP, 2 |
| EC-005 | Goal changed mid-day | User edits the daily goal during the day | The new target applies to the current day forward (BR-015). Past days keep the target in force that day. | FR-074, FR-084; BR-015 | MVP |
| EC-006 | Timezone change and DST | User changes the profile timezone, or a DST transition occurs | Each session stores its IANA zone and local date at its start; that local date is frozen and never recomputed. Today's progress after a change counts sessions whose frozen local date equals today's date in the new zone and nothing else. A streak is never reduced by the change (BR-022). On DST days a local day can be 23 or 25 h; the day-boundary rule BR-014 still applies and durations are unaffected because they are UTC based. | FR-006, FR-009, FR-047, FR-072, FR-089, FR-164; BR-014, BR-022, BR-030; NFR-091 | MVP |
| EC-007 | Subject deleted with history | User archives a subject that has sessions | Soft-delete (BR-029). Sessions and statistics are retained and labelled "<name> (archived)". Archiving is blocked with a message while a session is running on that subject. Its open plan entries and to-dos are hidden and return on restore. Its topics are hidden from pickers. Restore is available from the archived list. Hard purge happens only through account deletion. | FR-013, FR-014, FR-083, FR-104; BR-029; NFR-093 | MVP |
| EC-008 | Topic deleted | User archives a topic that has sessions or is on an exam checklist | Soft-delete. Sessions keep their subject and show the topic as archived. The exam checklist drops the topic from the readiness denominator and notes the change. | FR-018, FR-122, FR-126; BR-029 | MVP |
| EC-009 | Session crossing midnight | A session runs past 00:00 in its frozen zone | The session is split at the boundary (BR-016) and both parts count toward their own days. It is displayed as one session with two day-allocations. | FR-047, FR-061; BR-016 | MVP |
| EC-010 | Client clock is wrong | The device clock is ahead, behind or changed during a session | Durations use server timestamps only (BR-012). The client sends actions, not durations. | FR-040, FR-054; BR-012; NFR-090 | MVP |
| EC-011 | Manual entry in the future or overlapping | User adds or edits a manual session | A future start or end is rejected. An entry that overlaps a recorded session is rejected with a message naming the conflicting session (decision U-7). Maximum 24 h per entry. The total across all sessions of one day is capped at 24 h. | FR-042, FR-043, FR-088; BR-010 | MVP |
| EC-012 | Very short session | Timer stopped under 1 min, or a Pomodoro stopped under 5 min | Under 1 min is discarded (BR-008). A Pomodoro stopped at 5 min of focus or more counts as completed. Between 1 min and under 5 min it is saved as time only, not as a completed pomodoro (BR-007). A message states the result. | FR-045, FR-058; BR-007, BR-008 | MVP |
| EC-013 | Exam date in the past | User creates or edits an exam date | Creating with a past date is rejected. Editing to a past date after creation is allowed and the exam is archived on the next day. | FR-120, FR-121, FR-124, FR-038; BR-025 | MVP |
| EC-014 | Exam with all or no topics | Readiness is computed for an exam whose topics are all done or whose checklist is empty | All topics complete: readiness 100%. Zero topics: an "add topics" empty state is shown and no division by zero occurs. | FR-122, FR-126, FR-127; BR-024 | MVP, 2 |
| EC-015 | Invalid AI-generated schedule | The AI provider returns entries that break the rules | Each entry is validated. It is rejected if malformed, in the past, after the exam date, outside the user's declared available hours, of a duration outside 5-480 min, referencing an unknown subject or topic, or if the total exceeds the declared weekly hours. Rejected entries are dropped and counted in the preview (for example "3 entries removed"). If 0 entries are valid, an error is shown and nothing is saved. Overlaps with existing entries show warnings (BR-026). Nothing persists until the user accepts. A retry counts toward the 5/day limit only if a provider response was received. | FR-190, FR-193..196, FR-198; BR-025, BR-026 | 3 |
| EC-016 | AI provider unavailable | The provider errors or does not answer within 30 s | An error is shown. Nothing is partially saved. No quota is consumed. | FR-191, FR-196, FR-197 | 3 |
| EC-017 | Duplicate XP transactions | An award is retried, or a session is edited or deleted | Each award is unique per (user, source event, rule); a repeat is a no-op. Editing or deleting a session creates a compensating adjustment and never deletes ledger rows. The daily cap of 600 XP (BR-018) is applied when the award is made. A retried request cannot double-award. | FR-170..177; BR-017, BR-018, BR-019; NFR-095 | 2 |
| EC-018 | User leaves a study group | Member leaves, is removed, or an administrator leaves | The user disappears at once from the member list and all leaderboards. Their sessions and data are unaffected. Group-scoped shared statistics of the user are no longer visible. Rejoining needs a new invite. The last administrator cannot leave without transferring administration or dissolving the group (dissolving needs confirmation). If an administrator is removed by account deletion, the oldest member is promoted automatically. | FR-202..205, FR-210, FR-211; NFR-037 | 3 |
| EC-019 | Account deleted while in groups or timing | User deletes the account with a running timer or group memberships | The running timer is discarded, memberships are removed as in EC-018, and personal data is purged per NFR-031. | FR-007; BR-032; NFR-031 | MVP, 3 |
| EC-020 | Data synchronization conflicts | The same record is edited from two tabs or devices (there is no offline-first mode) | Editable records carry a version. A save on a stale version is rejected with "changed elsewhere" and the record reloads. For notes, both versions are shown and the user can keep mine, keep theirs or copy both (decision U-8). Timer state is server-authoritative and all clients converge within 5 s of a change; polling or push is an SDD choice. | FR-011, FR-016, FR-031, FR-043, FR-044, FR-059, FR-091, FR-100, FR-102, FR-103, FR-121, FR-212; NFR-094 | MVP |
| EC-021 | Duplicate session save | Retry or double-click on save | The save is idempotent by a client-generated request key; exactly one session is stored. | FR-048, FR-110; NFR-053 | MVP |
| EC-022 | Plan entry deleted with linked sessions | User deletes a plan entry that sessions are linked to | The sessions are retained and become unlinked (BR-003). | FR-032, FR-041; BR-003 | MVP |
| EC-023 | Invalid daily goal | User sets a goal of 0 or above 1440 | Rejected. The accepted range is 5-1440 minutes. | FR-070, FR-071; BR-013 | MVP |
| EC-024 | Permission denied or autoplay blocked | The browser denies notification permission or blocks audio | The feature degrades to an in-app indicator and the user is prompted to enable the permission. | FR-055, FR-150..153, FR-182 | MVP, 2 |
| EC-025 | Leaderboard fake-session attempt | Manual entries or very short sessions are used to gain rank | Manual entries and sessions under 5 min are excluded. Only server-recorded timer sessions count. | FR-207; BR-010 | 3 |
| EC-026 | API abuse or rate limit | A key exceeds 60 requests/min or is leaked | HTTP 429 with a retry-after value. The key can be revoked and revocation is immediate. | FR-222, FR-225, FR-226 | 3 |
| EC-027 | Export while data changes | User exports while sessions are still being saved | The export is a point-in-time snapshot taken at request time. | FR-130..132; BR-032 | MVP |
| EC-028 | Network loss during a session | Connection drops while the timer runs | The timer continues locally from the stored start time and syncs on reconnect. If the client is offline for more than 30 min, BR-006 applies on reconnect. | FR-046, FR-054; BR-006; NFR-051 | MVP |
