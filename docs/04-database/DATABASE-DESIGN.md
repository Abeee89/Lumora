# Database design

> Status: Proposal, pending approval. Source of truth: Phase 2 PRD and Phase 1 docs.

Scope: Lumora relational design on PostgreSQL (ADR-002). This phase produces documents only. No migration, SQL execution, Drizzle schema or application code exists yet. Companion documents: [CONCEPTUAL-ERD](CONCEPTUAL-ERD.md), [LOGICAL-ERD](LOGICAL-ERD.md), [PHYSICAL-ERD](PHYSICAL-ERD.md), [DATA-DICTIONARY](DATA-DICTIONARY.md), [DATABASE-CONSTRAINTS](DATABASE-CONSTRAINTS.md), [INDEXING-STRATEGY](INDEXING-STRATEGY.md), [DATA-LIFECYCLE](DATA-LIFECYCLE.md), [BACKUP-RESTORE](BACKUP-RESTORE.md).

The product is called Lumora in the repository. The Phase 4 brief used the placeholder "Study Tracker"; the two names refer to the same product.

## 1. Selection review

PostgreSQL (ADR-002) against the seven review criteria.

| Criterion | Verdict | Evidence |
| --- | --- | --- |
| Relational fit | Fits | Every entity is owned by one user and linked by identifiers; no document-shaped aggregate needs nesting. `jsonb` is used only for small opaque values (AI params and proposal, API key scopes, onboarding steps, idempotent response bodies). |
| Transactions | Fits | Services own the transaction (ADR-011). Multi-row changes in section 4 R10 commit atomically, including outbox rows (ADR-005). |
| Consistency | Fits | Foreign keys, CHECK, partial unique indexes and one exclusion constraint enforce NFR-092, NFR-094, NFR-095 and BR-011 in the database, not only in code. |
| Indexing | Fits | B-tree, partial and covering (`INCLUDE`) indexes serve every query shape in [INDEXING-STRATEGY](INDEXING-STRATEGY.md). |
| Query performance | Fits with a trigger | NFR-003 (24 months, 10,000 sessions, p95 1 s) and NFR-070 (5 million sessions) are met by `study_session_days` plus covering indexes. Rollup table is specified but not built until the measured trigger in R6. |
| Scalability | Fits | Vertical growth plus a read replica for statistics and exports; rollups as the second step (NFR-071). Partitioning is not planned: it would force every primary key to include the partition key, which is a rebuild. Accepted because 5 million session rows fit one table. |
| Backup and restore | Fits | Provider backups plus a weekly logical dump, restore to a new instance (NFR-100..104). Detail in [BACKUP-RESTORE](BACKUP-RESTORE.md). |

Requirements on the server:

- PostgreSQL major version 15 or newer. Needed for `ON DELETE SET NULL (column)` used on composite foreign keys.
- Extension `btree_gist`, needed by the exclusion constraint on `study_sessions`.
- `pg_stat_statements` is optional and used in the performance verification plan.

Contingency, extension: if the chosen platform lacks `btree_gist`, drop the exclusion constraint from `study_sessions` and perform the overlap check in the service under the per-user advisory lock (R9). No other table depends on it.

Contingency, version: if the platform offers PostgreSQL 14 or lower, see the alternate foreign key form in [DATABASE-CONSTRAINTS](DATABASE-CONSTRAINTS.md) section 9.

## 2. Conventions

| Topic | Rule |
| --- | --- |
| Naming | Tables and columns `snake_case`. Table names plural. Index names `ix_<table>_<cols>`, unique constraints `uq_<table>_<cols>`, checks `ck_<table>_<rule>`, foreign keys `fk_<table>_<column>`. |
| Identifiers | `uuid`, UUIDv7 generated by the application (time ordered, friendly to B-tree inserts). No database default. Better Auth id generation is to be configured for UUIDv7; this is unverified. If unsupported, the auth tables keep the library's text ids and every `user_id` column stays `uuid` through a cast mapping in the adapter. Decided in the Phase 7 auth spike (U-A4). |
| Instants | `timestamptz`, column suffix `_at`. Database and session time zone are UTC (NFR-091). |
| Calendar days | `date`, suffix `_date` or `_from`. |
| Durations | Integer `_seconds` for recorded study time (NFR-090), integer `_min` for planned or configured minutes. |
| Enumerations | `text` plus `CHECK (col IN (...))`. No PostgreSQL ENUM types, so adding a value is a plain backwards compatible migration (DEPLOYMENT stage 9). |
| Booleans | `is_` or `has_` prefix only when the name is otherwise ambiguous. |
| Optimistic concurrency | Editable records carry `version integer NOT NULL DEFAULT 1 CHECK (version >= 1)` (NFR-094, ADR-011). Update shape: `UPDATE t SET ..., version = version + 1 WHERE id = $1 AND user_id = $2 AND version = $3`. Zero rows updated means `stale_version`. |
| Ownership | Every user-owned table has `user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE` (NFR-016, NFR-092). |
| Text length | `char_length(btrim(col)) BETWEEN a AND b`. |
| Schemas | Application tables in `public`. pg-boss lives in schema `pgboss`, created by the library, excluded from Drizzle migrations and from the data dictionary. |
| Migrations | `drizzle-kit` generates SQL files committed to the repository. A separate migration step runs before traffic (DEPLOYMENT stage 9) under a migration role that owns the tables. The application role has DML only. Only expand and contract migrations. |
| Row-level security | Not used. A transaction pooler makes per-request `SET LOCAL` fragile. Ownership is enforced by repository scoping (NFR-016) and the composite foreign keys in [DATABASE-CONSTRAINTS](DATABASE-CONSTRAINTS.md) section 6. |
| Timestamps | `created_at timestamptz NOT NULL DEFAULT now()` on every table. `updated_at timestamptz NOT NULL DEFAULT now()`, set by the application, on every mutable table. |

## 4. Core rules

These rules are normative for Phase 7 implementation.

### R1. Plan versus session

`plan_entries` (intent) and `study_sessions` (fact) are separate tables with no shared columns (BR-001, BR-002). The link is the nullable `study_sessions.plan_entry_id` (BR-003). Planned minutes are `plan_entries.duration_min`. Actual minutes are the sum of `study_session_days.seconds` for linked sessions. Variance is computed and never stored (BR-004).

### R2. Timer persistence

Active timer state lives only in `timer_runs` (one row per active timer), with child `timer_run_segments` (focus intervals; `ended_at` is NULL while open).

- Pause closes the open segment. Resume opens a new one. Pomodoro break phases have no open segment.
- `UNIQUE (user_id)` on `timer_runs` is the one-timer rule (BR-011, ADR-011 item 4). Start is:

```sql
INSERT INTO timer_runs (...) VALUES (...)
ON CONFLICT (user_id) DO NOTHING
RETURNING id;
```

No row returned means `timer_already_running` (EC-002).

- Stop is one transaction: lock the run `FOR UPDATE`; close the open segment at `now()`; `duration_seconds` is the sum of segment lengths (BR-012, NFR-090); apply the BR-007 and BR-008 thresholds; insert `study_sessions` and `study_session_days` (each segment split at local-day boundaries in the frozen zone and rollover hour, BR-016); delete the run (segments cascade); write outbox and XP rows.
- Below 60 seconds: delete the run and insert nothing (BR-008, EC-012, FR-045). A completed or discarded timer therefore leaves no `timer_runs` row.
- The auto-close job selects `timer_runs WHERE last_heartbeat_at < now() - interval '30 minutes'` and performs the stop transaction at `last_heartbeat_at` with `auto_closed = true` (BR-006, EC-001, FR-046).
- Duplicate save prevention: `UNIQUE (user_id, request_key)` on `study_sessions` (EC-021, FR-048).
- Overlap prevention: the exclusion constraint in R9.
- Pomodoro durations in `timer_settings` are copied into the run at start, so later setting changes do not alter a running timer (FR-057).

### R3. XP ledger

`xp_ledger` is append-only. The application role has no UPDATE or DELETE grant, except deletion through the user cascade at account purge. There is no mutable total: XP total is `SUM(amount)` over the user's rows (covering index `(user_id) INCLUDE (amount)`).

- Uniqueness: `UNIQUE (user_id, source_type, source_key, rule, source_revision)` (NFR-095, EC-017). The first award uses `source_revision = 0`. Each compensating adjustment uses the source record's `version` after the edit, so retries are no-ops and distinct edits stack.
- Daily cap of 600 (BR-018): enforced at insert time in a transaction that first runs `SELECT ... FROM user_gamification WHERE user_id = $1 FOR UPDATE`, then reads `SUM(amount) WHERE user_id = $1 AND local_date = $2`. The cap value comes from application configuration (NFR-062).
- `source_key` is text (session uuid, to-do uuid, or `YYYY-MM-DD`) with no foreign key, so deleting a session or to-do never deletes XP rows. Compensation rows are added instead (BR-019).
- Level is a pure function of the sum and is not stored (FR-175).

### R4. Historical data on delete

| Record | Behaviour |
| --- | --- |
| Subject, topic | Never hard-deleted by users. `archived_at timestamptz` (BR-029, NFR-093, EC-007, EC-008). Foreign keys to `subjects` and `topics` use `ON DELETE NO ACTION`, not RESTRICT, so the account-purge cascade still works while accidental hard deletes are blocked. |
| Archive side effects | Archiving a subject hides its topics, open plan entries, to-dos, notes and per-subject goals through a join on `subjects.archived_at IS NULL`. There is no child flag to flip, so restore needs no data rewrite (FR-013, FR-014). A topic archived on its own has its own `archived_at`. |
| Plan entry | Hard delete. Sessions are unlinked by `ON DELETE SET NULL (plan_entry_id)` (EC-022). The plans module event `PlanEntryDeleted` is therefore not required for correctness. |
| Session | Hard delete by user action (FR-044). XP is corrected by compensation (R3). |
| To-do, flashcard | Hard delete. |
| Note | Hard delete while its subject is active. |
| Exam | Never deleted. Archived state is derived from `exam_date < today` in the profile zone (BR-025). There is no `archived_at`. This deviates from the BACKGROUND-JOBS "exam archive" job, which becomes optional and only emits `ExamArchived` (see section 5). |
| Account | `DELETE FROM users` cascades every owned row (BR-032, NFR-031, EC-019). |

### R5. Time zones

- Instants are UTC. `study_sessions.timezone`, `.local_date` and `.day_rollover_hour` are frozen at start and computed only by the shared time module (ADR-006). A profile change never updates them (BR-030, NFR-091, EC-006). `plan_entries` freeze `timezone` and `local_date` the same way when the start is created or edited.
- "Today" for goals, to-dos, exams, flashcards and reminders is computed from the current `user_profiles.timezone` and `rollover_hour` by the time module and passed to queries as a `date` parameter. No query calls `now() AT TIME ZONE <column>`.
- Midnight crossing (EC-009, BR-016): one `study_sessions` row plus one `study_session_days` row per local day touched. This is derived data allowed by ADR-006. It is written in the same transaction as the session and rewritten when times are edited. The boundary is local midnight shifted by `day_rollover_hour`.
- DST days of 23 or 25 hours do not change `duration_seconds`, which comes from instants (EC-006).
- Week runs Monday to Sunday in the member's zone (FR-207 group leaderboard). Weekly keys use the frozen `local_date`.

### R6. Statistics

| Kind | Items |
| --- | --- |
| Computed per request from base tables | Daily, weekly and monthly totals; totals by subject; calendar heatmap buckets; goal progress and goal-met; goal hit rate; planned versus actual; exam readiness; countdowns; to-do due states; flashcard queue; group leaderboard; current level; XP total. |
| Stored derived data | `study_session_days` (required for the midnight split and NFR-003); `daily_evaluations` and `user_gamification` (streak state; freeze usage and longest streak are history, FR-161..163). |

- No daily or monthly rollup table at MVP. Trigger from SDD: statistics p95 above 700 ms in the load test. Shape if triggered: `daily_rollups(user_id, local_date, subject_id, seconds, session_count)`, primary key `(user_id, local_date, subject_id)`, rebuilt from `study_session_days` by a job.
- Reconciliation (NFR-096): all aggregates sum seconds first and convert to minutes only at the presentation edge. A scheduled and test query asserts `SUM(study_session_days.seconds) = SUM(study_sessions.duration_seconds)` per user.

### R7. Study groups (Phase 3)

- Ownership: a group has no single owner row. Authority is `group_members.role = 'admin'`. `groups.created_by` is informational (`ON DELETE SET NULL`).
- Membership: `PRIMARY KEY (group_id, user_id)`. A user may be in many groups. Leaving or removal deletes the row (EC-018).
- Visibility: members see display name, role and, where `share_weekly_minutes = true`, the weekly total (NFR-037). No policy gives admins extra access.
- At least one admin and `max_members` are enforced by the service in a transaction that first locks the `groups` row `FOR UPDATE`. No trigger, because both are cross-row counts.
- Invites are single use (`accepted_by_user_id`, `accepted_at`). The token is stored as a SHA-256 hash and expires after 7 days. A used or revoked invite is refused, which also means rejoining needs a new invite (EC-018).
- Account deletion of the last admin: the purge handler promotes the member with the smallest `joined_at` before removing the user's membership (EC-019).

### R8. Idempotency

Two mechanisms (ADR-011 item 1).

1. A key column on the created row, when the row's lifetime equals the key's lifetime: `study_sessions.request_key` and `card_reviews.request_key`, each `UNIQUE (user_id, request_key)`. Nullable on sessions (NULL for server-originated rows such as auto-close). The service returns the existing row on conflict. Manual-entry replays use this mechanism (EC-021).
2. Table `idempotency_keys` for every other keyed creating action: timer start, plan entry, to-do, note, subject, topic, exam and flashcard create, bulk topic create, AI accept, export request, API key create. `PRIMARY KEY (user_id, scope, key)` with `request_hash`, `response_status`, `response_body jsonb`, `created_at`, `expires_at`. Retention is 7 days, then the daily cleanup job deletes the rows. This resolves the retention question ADR-011 deferred: client retry windows are minutes, and 7 days covers offline tab restarts.

### R9. Concurrency and locking

- Optimistic `version` on all editable records (NFR-094, EC-020).
- Per-user advisory transaction lock `pg_advisory_xact_lock(hashtextextended('user:' || user_id::text, 0))`, taken only by manual-session create or edit (24 hour per-day cap check over `study_session_days`, overlap against a running timer's `started_at` to now) and by API key create (10 active maximum).
- Exclusion constraint on `study_sessions`:

```sql
EXCLUDE USING gist (
  user_id WITH =,
  tstzrange(started_at, ended_at, '[)') WITH &&
)
```

A violation is mapped to the "overlaps session X" message (U-7, EC-011). Manual create also checks `started_at < ended_at <= now()` in the service, with `ended_at > started_at` as a CHECK.

- Isolation level READ COMMITTED everywhere, except exports, which use `REPEATABLE READ READ ONLY` for a point-in-time snapshot (EC-027). No SERIALIZABLE.

### R10. Transaction boundaries

| Operation | One transaction contains |
| --- | --- |
| Session stop or save | Lock run, close segment, insert session and days, delete run, XP and outbox rows |
| Manual session add, edit, delete | Advisory lock, session, days rewrite, XP compensation, outbox |
| Plan entry delete | Single DELETE; the FK action runs in the same statement |
| Subject archive | Guard check against `timer_runs` plus the `archived_at` update |
| Exam checklist set | Delete and insert of `exam_topics` |
| Bulk topic create | All topics or none (FR-017) |
| Flashcard rate | Review row, card schedule update, daily limit count |
| AI accept | All plan entries, `accepted_at`, idempotency row |
| Group join | Lock group row, count members, insert member |
| Account purge | Per-module handlers, then `DELETE FROM users` |
| Export | Single `REPEATABLE READ READ ONLY` snapshot |
| Any outbox write | Same transaction as its business change (ADR-005) |

## 6. Worked examples

These can be checked on paper against the tables.

**E1. Two simultaneous timer starts for one user (BR-011, EC-002).** Tab A and tab B both run the R2 insert. The unique index on `timer_runs(user_id)` lets one statement insert; the other hits `ON CONFLICT DO NOTHING` and returns no row. The service answers `timer_already_running` to tab B and offers to stop the first. Exactly one `timer_runs` row exists afterwards.

**E2. Session crossing midnight in `Europe/Paris`, rollover hour 0 (EC-009, BR-016).** A timer runs from 2025-03-10 22:30 to 2025-03-11 00:30 local time. `study_sessions` holds one row with `timezone = 'Europe/Paris'`, `local_date = 2025-03-10`, `duration_seconds = 7200`. `study_session_days` holds `(session, 2025-03-10, 5400)` and `(session, 2025-03-11, 1800)`. The two `seconds` values sum to 7200, so the reconciliation query in R6 holds.

**E3. Deleting a plan entry with linked sessions (EC-022).** `DELETE FROM plan_entries WHERE id = $1 AND user_id = $2`. The composite foreign key `(plan_entry_id, user_id)` on `study_sessions` has `ON DELETE SET NULL (plan_entry_id)`. Sessions keep all other columns, including `user_id`, and their `plan_entry_id` becomes NULL. Statistics are unchanged because they read `study_session_days`.

**E4. Retrying an XP award (EC-017, NFR-095).** First insert: `(u, 'session', S, 'focus_minutes', 0)` succeeds. A retry with the same tuple violates `uq_xp_ledger_award` and is treated as a no-op. After the session is edited to `version = 2`, the compensating row `(u, 'session', S, 'adjustment', 2)` is a distinct tuple and inserts once.
